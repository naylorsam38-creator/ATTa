## Bugs in v121.1 found and fixed, each with a failing test first

1. **Revision `unknown` inside the Coolify container.** Every app would have been UNVERIFIED and nothing could ever reach Coolify. This was reproduced on the unmodified v121.1 code.
2. **Job identity written to `state/apps/<app>.json`.** The loop watcher stamped a finished job's run and revision onto its own later checks.
3. **One evidence folder per app.** Each new check overwrote the pictures that an older result still pointed at.
4. **`pool.map` plus a `_synth` that needs the app's folder.** One exception outside the check aborted the whole fleet.
5. **No rerun when the revision changed**, only a mark.
6. **No hard timeout.** One hung job blocked the fleet and its report.
7. **Identity collisions merged**, so two apps shared everything.
8. **No aggregate report**, and sequential runs could happen unrecorded.
9. **`evidence.jsonl` rows had no identity.**
10. **`app_runner.py all` raised a NameError on `out`.** This is also in v121.
11. **The two version-pin tests failed.**
12. **The deployment PR's kit fix (Docker Hub mirror, multi-domain) was missing.**

## Not verified here

A live fleet run on the server. It needs Docker and the stopped ATTa service, and ATTa stays stopped until you say otherwise. When approved, the check is:

2. After the run, read `state/runner/RUN-REPORT.md`. Expect `mode parallel` with a peak above 1, one row per app, and `deployment revision … (stable)`.

## v121.3: the stop → record → one bounded fix → retest process

| Process step | Implementation | Proof (test) |
|---|---|---|
| A stage fails: stop that app at that stage | The watcher stops at the first FAIL; the repair cycle starts from it | every StopFixRetest test |
| Record where, the error, logs, evidence, stage, attempt, app, revision and class; never overwrite | `failures/<app>/<run>-a<n>-f<k>.json` plus `.container.log` (captured while the app is up); unique names | `test_failure_is_recorded_…`, `test_same_failure_after_the_fix_…` (both records kept) |
| Do not rerun an unchanged test | No retest when no fix exists, a person is needed, or the fix changed nothing. Warm-up waits and start retries stop on an identical failure | `test_no_evidence_based_fix_…`, `test_a_fix_that_changes_nothing_…`, `test_warmup_waits_stop_…`, `test_same_start_failure_after_a_fix_…` |
| One bounded fix from the existing ATTa repair process | Tier 1 known fixes, tier 2 capability adapter, using the real `repair_actions`. No blind probe. Never the same fix twice | `test_failure_is_recorded_…` (real `chmod_launcher`), `test_known_human_only_failure_…` |
| Retest the failed stage; restart only if the fix touched the start | The watcher runs on the running app (stages 1-5 re-checked as regression); the runner is used only for start-class fixes | `test_failure_is_recorded_…` (`run_app` called once, 2 checks) |
| Same failure again: record it and stop | FIX_DID_NOT_RESOLVE; the learned rule is marked failed | `test_same_failure_after_the_fix_stops_the_app_no_loop` |
| Passes: continue to final verification | RESOLVED, then the barrier on the post-fix revision, then QUALIFIED (verified) | `test_failure_is_recorded_…` |
| Required regression checks | App repair: every stage of that app is re-checked. Shared repair: apps that qualified before it are re-checked at the end of the run | `test_a_shared_repair_rechecks_apps_that_qualified_before_it` |
| Each repair and retest has its own evidence and revision identity | New correlation ID and revision snapshot per retest; evidence folder `…-r<n>` | `test_failure_is_recorded_…` |
| Other apps keep running | Each app's cycle runs inside its own job | `test_other_apps_finish_while_one_is_in_repair` |
| Failure report (the 8 requested columns plus repair history) | `RUN-REPORT.md` "Failure report" and `RUN-REPORT.json` `failure_report` | `test_other_apps_finish_while_one_is_in_repair` |
| The post-build self-healer does not blindly re-run | In-job-repaired items skip tiers 1-2 and the probe; no catalogue re-run unless a fix was applied | `test_heal_does_not_repeat_in_job_repairs_or_rerun_the_catalogue` |
