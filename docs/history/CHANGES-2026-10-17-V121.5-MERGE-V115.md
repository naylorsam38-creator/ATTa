# v121.5 — v121.4 with the v115 security work merged in

v117 was built on v114.2, so every release from v117 to v121.4 shipped without v115's security fixes.
v121.5 is v121.4 (all of v117–v121.4, unchanged in behaviour) plus `v115-complete.patch`, ported.

## What v115 brings (see CHANGES-2026-09-25-V115-SECURITY.md)
- Apps never receive ATTa's environment: compose and the runner use `app_env.runner_env()`.
- Stage-6 evidence is data: `page.html` downloads as text with a sandbox CSP; owner-only; symlinks refused.
- Builds are trusted by `origin` (`web` / `local`), never by owner name; reserved names can't be accounts.
- Cross-site POSTs refused (Sec-Fetch-Site / Origin); security headers on every page.
- Customer integration tokens go straight to the app's Coolify resource; ATTa keeps a fingerprint only.

## Merge fixes (conflicts the patch tool could not see)
1. **Container first run.** v117's container mode queued its whole-library run by writing
   `<id>.library.json` into the web inbox with no build record. v115 refuses exactly that, so under Coolify
   the first run would never have happened. It now goes through the root-only `local-inbox/` (0700, file 0600),
   which v115 checks and records as origin `local`. The pipeline picks up `*.library.json` there.
2. **Skin proxy environment.** v117+ starts each app's skin proxy (`.ui-capability/run-ui.sh`, inside the
   app's folder) with ATTa's whole environment — session secret, Coolify token, model key. It now gets
   `runner_env()` plus only the three skin settings the proxy reads (the same ones `coolify_provision.SKIN_ENV`
   gives the live proxy).
3. **Journey account exec** (`journey_author.py`, v121) now runs `docker compose exec` with `runner_env()`.
4. **Coolify resource kind.** Services ATTa creates (v117, `POST /api/v1/services`) were stored as bare UUIDs,
   which v115's `resource_for` read as *applications*, so customer tokens would have gone to the wrong endpoint.
   Services listed under `managed_by_atta` now resolve as `service`; `_remember` records the kind.
5. **Evidence route.** v121.2's per-run path `/evidence/<app>/<run>/<file>` kept, with v115's ownership,
   symlink and data-only rules added. Only the three evidence file names are served (stricter than v115's
   "any name as a download"); the v115 test was changed to expect 404 for other names.
6. Owner filtering of apps and evidence in build pages, token links in the library, `/apps/<app>/secrets`.

## Tests
241 passed, 19 skipped, 8 failed. The 8 are the browser tests (`test_v119_login_proof.py`,
`test_v121_journey_author.py`) and fail identically on untouched v121.4 in an environment without Chromium.
New: `V121_5MergeFixes` (skin proxy gets no ATTa secrets — fails on v121.4 code; service resources resolve
as services), container-first-run and local-inbox library-run tests. Tests that created builds without an
origin now pass `origin="web"`; version tests expect v121.5.

## Labels
`release.json` now says v121.5 (v121.4 still said v121.2) and lists the v121.2-diagnostic, v121.3, v121.4,
v115 and v121.5 features. `V121.3-ADDITIVE-CONTROL-LAYER.md` (removed in v121.4) restored here as history.
