# v121.3 additive control layer

This release adds `04-deployment/atta_control/` around the existing ATTa machinery.

## Hard preservation rule

Nothing in the v121.2 runner, discovery, watcher, known-fix store, capability adapter,
LLM repair, repair actions, rule lifecycle, Coolify handoff, or existing reports is removed.

The control layer does not launch apps and does not create a second repair engine. It adds:

- explicit app/run/attempt/correlation identity
- evidence timestamp/fingerprint checks
- exact classification + repair-action policy
- authorization immediately before an existing repair callback
- append-only observations, repair audit, and run-event journals
- deployment verification state
- additive JSON/Markdown report helpers
- an adapter contract for wiring to actual ATTa records

## Compatibility

`ATTA_CONTROL_ENFORCE=0` (default) records the control decision and executes the existing
repair path even if an old record lacks fields needed by the new gate. This preserves v121.2
self-healing behavior while the new records are populated.

Set `ATTA_CONTROL_ENFORCE=1` after live records have been verified to contain the required
identity/evidence fields. In enforced mode, an unidentifiable or stale repair is blocked rather
than mutating state.

Existing repair actions remain the only mutations. Existing tier order remains:

known fix -> capability adapter -> LLM/script probe -> human.

The new layer sits immediately around the mutation boundary and records what happened.
