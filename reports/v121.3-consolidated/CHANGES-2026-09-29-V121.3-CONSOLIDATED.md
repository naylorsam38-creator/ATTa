# ATTa v121.3-consolidated

ATTa v121.3-consolidated combines four supplied ATTa zips, the v121.3 that runs on the server and the v121 bundle the server was first installed from into one release. Nothing that any of those versions has was removed. This page says:

- exactly where each part came from;
- what was merged;
- the three things added during consolidation, and why each was needed.

The complete file-by-file list (all 153 files, with where each came from and what it does) is in `docs/SYSTEM-INVENTORY.md`. That list is generated from the files themselves, and checks all five sources.

## 2. How they were merged

The merge was three-way:
- **Base:** v121.2 (`5f7bbe7`).
- **Side A:** the server v121.3 (`684d768`).
- **Side B:** the additive-control release.

Only one file was touched by both sides in a way that clashed: `release.json`. Each side appended its own feature line, and both lines are kept.

`maintenance.py` was changed by both sides in different places, and it merged cleanly.

**Proof that nothing was dropped.** A script checked every one of the 23 files either side changed:
- every block of lines either side **added** is present in the result;
- no block either side **removed** is back.

The result: 0 problems. Every file of v121, v121.2, the server v121.3, the additive-control release and the server's original bundle is present; none is missing.

## 3. What each part contributes

### From v121 (the base, unchanged unless listed)

This is the whole working system:

- **Web entry point.**
  - `gateway.py`: login, Front Door, upload, builds, library, status and alerts.
  - `accounts.py`: salted PBKDF2 accounts, admin or user.
  - `builds.py`: build records owned by the account that started them.
- **Library.**
  - `app_discovery.py`: finds every app in an upload.
  - `catalogue_sync.py` and `app_classifier.py`: work out each app's code root, skin category and profile from its own files.
  - `intake.py`: fixed-rule intake checks.
  - `upstream.py` and `runtimes.py`: how to run an app that doesn't say how.
- **Pipeline.** `pipeline.py` takes an item from the inbox, then catalogues it, installs the skin, runs intake, and qualifies it. It then hands off to Coolify.
- **Running apps.** `app_runner.py` starts each app the first way that works: its compose file, a published image, its Dockerfile, or a runtime. It adapts the way of starting before giving up, and puts the skin proxy in front.
- **The six-stage check.** `system_watcher.py` runs 1 INSTALLED → 2 APP_UP → 3 PROXY_UP → 4 SKIN → 5 HOOK → 6 CLEAN. Stage 6 is a real Playwright browser, with a login or smoke journey authored by `journey_author.py`.
- **Self-healing tiers.**

  | Tier | Module | Does |
  |---|---|---|
  | 1 | `known_fixes.py` | Deterministic known fixes |
  | 2 | `capability_adapter.py` | Capability adapter |
  | 3 | `llm_repair.py` | LLM diagnosis, secrets stripped by `redact.py` |
  | 4 | `alerts.py` | Tells a person |

  Supporting these:
  - `maintenance.py` drives the tiers;
  - `repair_actions.py` is the only thing allowed to change anything;
  - `rule_lifecycle.py` governs trust in learned rules;
  - `failure_keys.py` gives each failure one key;
  - `syntax_triage.py` separates syntax slips from real breakage.
- **Hand-off.**
  - `coolify_handoff.py` and `coolify_provision.py`: only QUALIFIED apps go to Coolify, each as its own service.
  - `user_catalogue.py`: people only ever see qualified, live apps.
- **Deployment of ATTa itself.**
  - `deployd/` (ADM): stage, check, back up, activate, health check, roll back.
  - `bootstrap.sh`, `container_main.py` and `docker-compose.coolify.yml`: run ATTa under Coolify.
  - The `05-coolify/kit` scripts: install, deploy, verify, back up and restore.
- **Specs, skins and front door.** `01-specs/`, `03-ui-skins-capability-package/` and `02-front-door/front-door.html`.

### Added by v121.2 (11 new files, 13 changed)

- **Parallel isolated jobs.** Every app runs in parallel as its own job, with its own:
  - run ID and correlation ID;
  - workspace, containers and ports;
  - browser;
  - evidence folder, `evidence/<app>/<run>-a<n>/`.
- **Containment.** One app crashing, hanging or vanishing becomes that app's own result and never stops or hides another app's.
- **Revision barrier.**
  - The deployment revision and the app revision are captured before and after each check. If either changed, the check is rerun; if it keeps changing, the app is UNVERIFIED.
  - `resilience/identity.py` computes the revisions.
  - `resilience/probes.py` does safe probing: TCP reachability is recorded as evidence only, not as health.
- **Outcome states.** `resilience/states.py` gives each app exactly one of NOT_STARTED, START_FAILED, TIMEOUT, INCONCLUSIVE, FAILED, QUALIFIED or UNVERIFIED.
- **Fleet report.** `resilience/report.py` writes `RUN-REPORT.md` / `.json`.
- **Coolify kit.** Docker Hub registry mirror, and multi-domain `--domain`.

### Added by the server's v121.3 (3 new files, 5 changed)

`resilience/failures.py`, `app_runner.py` and `maintenance.py` implement test → fail → stop that app → record where → one bounded fix → retest:

- **Failure records.** Every failure is kept permanently at `failures/<app>/<run>-a<n>-f<k>.json`, with a `.container.log` beside it.
- **One bounded fix.** Exactly one fix is chosen from ATTa's own tiers, applied, and then:
  - the failed stage is retested;
  - the earlier stages are re-checked as a regression.
- **Stopping rules.**
  - No blind retries.
  - The same failure after a fix counts as FIX_DID_NOT_RESOLVE and stops.
  - A fix that changed nothing is not retested.
  - With no evidence-based fix, the app stops at NO_MATCHING_REPAIR and is reported.

### Added by the additive-control release (10 new files, 3 changed)

`atta_control/` wraps ATTa's existing repair actions; it never replaces them:

| Module | Role |
|---|---|
| `models.py` | App / run / attempt / correlation identity, and revisions |
| `policy.py` | Explicit (classification, action) → AUTO / APPROVAL_REQUIRED / ESCALATE. Anything the policy doesn't name escalates. |
| `gate.py` | Authorizes each repair just before it runs: identity complete, evidence fresh and unchanged, policy allows |
| `store.py` | Append-only audit journals in `state/control/` |
| `adapter.py` / `integration.py` | Bridge to ATTa's records |
| `report.py` | Report helpers |

- `maintenance.py` and `llm_repair.py` route each repair action through `authorize_and_run`.
- **Default `ATTA_CONTROL_ENFORCE=0`:** decisions are recorded and the repair runs exactly as before.
- **`ATTA_CONTROL_ENFORCE=1`:** an unidentifiable or stale repair is refused.

## 4. Added during consolidation (and why)

Four changes, each needed to make the combined system whole. None of them removes behaviour.

1. **The control gate now also covers v121.3's in-job repairs** (`app_runner._apply`).
   - **Why:** the additive-control release was built on v121.2, before v121.3 existed. It gated only `maintenance.py` (the self-healing that runs after a build). v121.3's own repair cycle, which runs inside each app's job, called `repair_actions` directly, so the "authorize every repair" promise had a hole.
   - **Now:** each in-job action goes through the same `authorize_and_run`. It carries the job's own run ID, correlation ID, attempt, app revision and deployment revision, and the failure record's time.
   - **Default:** audit only, so behaviour is unchanged.
   - **With `ATTA_CONTROL_ENFORCE=1`:** a refused repair becomes FIX_FAILED with the reason, and the app is not changed.
   - **Tests:** `tests/test_consolidated_control.py`. I also checked the reverse: both tests fail when the wiring is removed.
2. **A test-isolation bug in v121.3's own tests was fixed** (`tests/test_v121_3_stop_fix_retest.py`, harness only).
   - **The bug:** its `_Env` harness swapped in freshly imported ATTa modules and a temporary root, and never put them back. Any test file that ran before `test_v117_coolify.py` broke 9 of its tests.
   - **Why it went unnoticed:** the v121.3 file happened to sort after `test_v117`.
   - **Now:** the harness restores the modules and environment after each test. No product code changed.
3. **The server's original bundle's collection rule is back.** Restored from `ATTa-v121-collect-all-adaptive`:
   - `COLLECT-ALL-APPS.md` and `DISPATCH-RUNBOOK.md`.
   - In `run`, the "APP LIBRARY COLLECTION CONTRACT" header and `export APP_BUILDER_RUN_PARALLEL="${APP_BUILDER_RUN_PARALLEL:-0}"`. `run` is now byte-identical to that bundle's.
   - In `README.md`, the seed-list paragraph with the "collect every VERIFIED entry" rule.
   - In `upstream_apps.json`, the `collection: ALL_ENTRIES` and `collection_instruction` fields. The 43 app entries were already identical, and they keep the `number` field v121.2 added.

   Behaviour is unchanged: the runner already defaults to `APP_BUILDER_RUN_PARALLEL=0` (every app at once). What comes back is the written rule.
4. **Version bookkeeping.**
   - `release.json` is `v121.3-consolidated` and keeps every feature line of both v121.3s.
   - The two tests that pin the version string (`test_v117_coolify.py` and `test_v120_stage2.py`) were updated, as every earlier release did.

## 6. What this release does not do

Stated so that nothing is claimed that isn't there:
- It does not record Playwright video.
- It does not click every button on a page. Stage 6 runs one authored login or smoke journey, as in v121.
- It does not include the v121.4 control-layer rework or the record-diagnostic zip. Those were sent separately and were not among the four zips consolidated here.
- It does not include the unreleased v121.3.1 fixes or the live-run dashboard built in this session. Each can be added on top if you ask.
